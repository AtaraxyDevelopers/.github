# Contributing to public projects

Thank you for helping improve Ataraxy Developers' public projects.

1. Read the repository's README and any project-specific contribution guidance.
2. For a substantial change, open an issue describing the problem and proposed approach before implementation.
3. Keep pull requests focused. Explain the behavior that changes, why it matters, and how you checked it.
4. Use sample data. Never commit credentials, customer records, private configuration, or production backups.
5. Include relevant screenshots for interface changes and reproducible steps for bug fixes.

Review timing depends on maintainer availability. Please communicate respectfully and describe the work clearly.

Security concerns belong in the private channel described in [SECURITY.md](SECURITY.md), rather than a public issue.
